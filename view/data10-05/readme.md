# data10-05 · 생산진도율 자동화

현장 실적을 휴대폰으로 넣고 고객사 발주서·납품이력·재고현황 엑셀을 모아, 일자별 예상재고·과부족, 품번·납기별 생산진도율, 공정별 실적과 근무 투입조정 알림을 만드는 브라우저 도구

| 항목 | 내용 |
|---|---|
| 제출자 | 박주헌 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-10-20) · **2차 반영 — 실제 양식 3종 (2026-10-21)** — https://aebonlee.github.io/data10-05/ |
| 다음 개발 | 발주 품번 ↔ 재고 모델 대응표·월 물량·공정 리드타임 값 받기(기획서 10장 5~7), 고객사 포털(SRM) 자동 받기, 실적 공유 DB(프레임 제작팀과 함께), 긴급 알림 발송 |

> 과제는 패들릿으로 접수했습니다. 2026-10-21 받은 실제 양식(재고 체크 통합문서·포털 발주서·수기 양식 사진)에 맞춰 가져오기와 입력 화면을 고쳤습니다. 실제 값·품번·고객사는 리포에 넣지 않았고, 샘플은 **같은 모양의 가짜 값**입니다(모델 SMP-M20…, 품번 SMP-P…, 고객사A). 회사 이름은 리포에 적지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-05/**

처음 열면 「데이터 가져오기」 화면입니다. **「가상 샘플로 시작」** 을 누르면 가상 자료가 들어가고 대시보드로 넘어갑니다. 일부러 심어 둔 두 가지가 바로 보입니다 — **로봇 공정 병목**(그동안 잔업으로 버텨 왔고 최근 능률도 떨어짐), 그 때문에 **SMP-K30B 다음 주 결품 예상·뒤 공정 재공 부족**.
실제로 쓸 때는 **재고 체크 통합문서(날짜마다 시트)와 포털에서 내려받은 발주서 엑셀을 그대로 한꺼번에** 넣으면 됩니다. 모든 날짜 시트를 읽어 최근 체크를 재고·공정 재공으로, 두 체크의 차이를 공정별 실적으로 씁니다. 발주서는 늘 비어 있는 열을 건너뛰고 「납기요청일시」「납입지시수량」을 알아서 연결하며, 한 번 맞춘 열 연결은 다음에도 그대로 씁니다. 현장에서는 휴대폰으로 같은 주소를 열어 「실적 입력 → 재고 체크」에 수기 양식과 같은 칸 순서로 적습니다. 설정에서 **발주 품번 → 재고 모델 연결**, **근무일수·공정별 리드타임**을 적으면 「월 물량 ÷ 근무일수 × 리드타임」으로 공정별 안전재고를 계산해 알림을 냅니다. 파일과 자료는 서버로 보내지 않고 이 브라우저 안에서만 읽고 저장합니다.

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS).

| 화면 | 하는 일 |
|---|---|
| 대시보드 | 알림 목록(긴급·경고·주의·정보 — 재고 과부족·근무 투입조정·공정 안전재고·공정 능률·납기 진도·자료 점검), 요약 타일 4개, 공정 부하 막대·결품 위험 품번 예상재고 그래프, 공유 글 복사, 분석 엑셀(11개 시트) |
| ① 실적 입력 | 탭 두 개. **재고 체크** — 현장 수기 양식과 같은 칸(모델마다 출하(누계)·완성·도킹·가공·MT·사상·로봇, 가접 투입 누계는 자동)·합계 줄·체크 날짜와 시각·직전 체크 값 채우기·같은 모양 엑셀 받기. **공정 실적** — 일자·공정(큰 버튼)·품번(목록)·수량·작업자수·작업시간·비고, 칸마다 오류 안내, 「실적 표준 형식」 엑셀 받기 |
| ② 데이터 가져오기 | **재고 체크 통합문서(날짜별 시트) 한 번에 — 빈 양식·주차 집계·같은 날 두 번째 시트는 이유를 보여 주고 건너뜀, 누계가 줄어든 곳 목록** · **포털(SRM) 발주서 — 빈 열은 연결하지 않음, 한 행 = 1대, 기납품수량 반영** · 여러 파일 한꺼번에 · 제목 줄 건너 머리행 찾기 · 자료 종류(재고현황·발주서·납품이력·생산실적) 자동 판별 · 열 연결 확인/수정과 저장 · 고객사 열이 없으면 파일 이름에서 고객사 · 재고 기준일을 제목 줄·파일 이름에서 · 합계 행 건너뜀 · 같은 발주는 새 값으로, 같은 납품·실적은 한 번만 · 포털 자동 다운로드가 2단계인 이유 안내 |
| ③ 재고 과부족 | 재고 = 기초재고 + 완성 공정 실적 − 납품, 품번별 현재고·안전재고·최저 예상재고·부족수량·첫 부족일·결품 예상일, 품번별 일자별 예상재고 그래프·표, 예상 생산(최근 평균 완성) 반영 켜고 끄기 |
| ④ 생산진도율 | 품번별 진도율과 공정별 누적 실적(재공 추정), 발주·납기별 진도율 = (출하 완료 + 완성재고 충당) ÷ 발주수량, 예상 충당일, 상태(출하 완료·재고 확보·진행 중·지연 우려·납기 지남), 고객사·상태 거르기 |
| ⑤ 공정 분석 | **공정별 안전재고(재공) 판정 — 평균 일 출하대수 × 리드타임 vs 지금 재공** · 근무 투입조정 카드(필요 인시 vs 가용 인시, 가장 빠듯한 날, 하루 추가 인원 / 여유 인시), 공정·품번별 필요 인시, 공정별 평균·기준·최근 능률, 일자별·주별 시간당 생산·능률·일 목표 달성 그래프와 표 |
| ⑥ AI 분석 | 계산된 사실만 담은 프롬프트 — **품번(품목1)·고객사(거래처1)를 별칭으로 가림(기본)**, 대응표는 이 PC 에만, AI 답은 실제 이름으로 되돌림(복사·붙여 넣기, 선택: 본인 키로 OpenAI 호환 서버에 자동 보내기) |
| 설정 | 공정(순서·인원·근무시간·표준 개/인시·일 목표·**리드타임**), **안전재고 산식(월 물량 볼 달·근무일수·완성 리드타임·월 물량 직접 입력)**, **발주 품번 → 재고 모델 연결(세트·합계)**, 기준일·보는 기간·안전재고·알림 기준, 근무 요일·휴일, AI 연결, JSON 백업·불러오기, 엑셀 내보내기 |

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| 1) 실적 현장 전산입력 | 완료(브라우저 저장) | 휴대폰 입력 화면 + 엑셀 넣기. 여러 사람이 같은 자료를 보는 공유 DB 는 2단계 |
| 2) 고객사 발주서·납품이력 자동다운로드 | 일부(엑셀 업로드) | 고객사별 양식이 달라도 여러 파일을 한 번에 읽고 열 연결을 저장. 포털 자동 로그인·내려받기는 포털별 확인 후 2단계 |
| 3) 출하 대비 재고현황 자동 산출 | 완료 | 일자별 예상재고·과부족·안전재고 알림 |
| 재고 과부족 알림 | 완료 | 긴급·결품 예상·안전재고 미달 |
| 공정별 근무 투입조정 알림 | 완료 | 남은 발주 기준 필요 인시 vs 가용 인시, 하루 추가 인원 |
| 공정별 실적 분석 | 완료 | 시간당 생산·능률·일 목표 대비. 생산계획 대비는 계획 양식을 받은 뒤 |
| 실적 공유(프레임 제작팀) | 2단계 | 실적 표준 형식으로 저장·내보내기 — 공유 DB 의 표 모양을 미리 맞춤 |
