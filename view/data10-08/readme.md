# data10-08 · 프레임 제작 생산성 개선

일일 실적으로 목표 대수 대비 달성률(90% 선)을 관리하고, 현장 측정으로 공정별 작업시간·손실을 재어 병목공정·인원 배분·개선 전후 단가 절감을 분석하며 표준작업서 초안을 만드는 브라우저 도구

| 항목 | 내용 |
|---|---|
| 제출자 | 박상선 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-10-20) — https://aebonlee.github.io/data10-08/ |
| 다음 개발 | 2단계 — 실제 실적·측정 자료로 계산 정의 보정(가용시간·투입공수·원가), 한 사람만 할 수 있는 작업·선후 관계를 반영한 인원 배분, 팀 공유 저장소, 기존 작업표준서 근거 확인 |

> 과제는 패들릿으로 접수했습니다. 첨부 자료는 아직 없고, 이 리포의 샘플은 모두 **가상 값**입니다(작업자A~I, 가짜 임률·원가). 회사명은 리포에 두지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-08/**

처음 열면 「대시보드」입니다. **「가상 샘플로 시작」** 을 누르면 일일 실적 7주와 현장 측정 5일(개선 전 3일 · 개선 후 2일)이 들어갑니다.
샘플에는 일부러 **개선 전에는 본용접이 병목**(사이클타임 약 55분 > 택트타임 45분)이고 **「대기」 손실이 가장 크게**, 09/21 인원 배분을 바꾼 뒤에는 **달성률이 90%를 넘게** 만들어 두었습니다. 화면 위 기간 단추(「개선 전」「개선 후」)로 바꿔 보세요.

실제로 쓸 때는 「일일 실적」에서 날마다 입력하거나 엑셀을 넣고, 공정별 시간이 없으면 「현장 측정」에서 2~3일 잽니다(휴대폰 스톱워치 또는 빈 측정표 인쇄). 파일은 서버로 보내지 않고 이 브라우저 안에서만 읽고 저장합니다.

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS).

| 화면 | 하는 일 |
|---|---|
| 대시보드 | 최근 주·전체 달성률, 병목공정, 가장 큰 손실, 주별 달성률(90% 선) 그래프, 진행 순서 |
| 일일 실적 | 현장 실적 입력(일자·목표·실제·인원·가용시간·비고, 달성률·택트 미리 보기) · 엑셀 가져오기(머리행·열 자동 찾기, 직접 연결, 같은 날짜는 새 값) · 고치기/지우기 · 빈 양식·내려받기 |
| 달성률 관리표 | 일·주·월 묶기, 기간(전체·개선 전·개선 후·최근 2주·직접), 목표 vs 실제·달성률(90% 선) 그래프, 90% 이상 일수, 대당 투입공수, 엑셀(일·주·월 3시트)·인쇄 |
| 현장 측정 | 휴대폰 스톱워치(작업·자재 준비·이동·대기·재작업·기타 — 누를 때마다 구간 전환, 다음 대, 새로 고쳐도 이어짐, 방금 구간 메모) · 빈 측정표 인쇄·엑셀 · 손으로 한 행 넣기 · 측정 엑셀 가져오기 · 기록 목록 |
| 병목 분석 | 공정별 대당 순작업 공수·측정 인원·사이클타임 vs 택트타임, 라인 밸런스 그래프(택트 점선), 병목·택트 초과 판정, 하루 최대 대수·예상 달성률·라인 밸런스 효율, 측정/표준 기준 전환, 엑셀 |
| 손실 분석 | 손실 파레토(유형별·누적 비율), 공정별·작업자별 손실, 자주 적힌 사유, 엑셀 |
| 인원 배분 | 공정별 인원·공수 줄임(%) 바꿔 보기 → 사이클타임·병목·하루 최대 대수·예상 달성률, **같은 총인원 자동 배분 제안** |
| 개선 전·후 | 두 기간 비교(달성률·실제 대수·대당 투입공수·병목·손실 유형별), 임률·기타 원가 입력 → 대당 제작원가·절감액·절감률·연간 절감, KPI 3개(인원 유지·달성률 90%·단가 절감), 엑셀·Word·인쇄 |
| 표준작업서 | 공정 순서·인원·표준 공수·사이클타임·작업 요점·품질/안전 주의 표, 결재 칸 — 인쇄/PDF·Word·엑셀, AI 로 문장 다듬기(반자동) |
| 개선 보고서 · AI | 계산한 사실만 담은 AI 프롬프트 — **작업자 이름은 「작업자1」 같은 별칭으로 가림(기본)**, 원가는 켤 때만, AI 답은 이름으로 되돌림(복사·붙여 넣기, 선택: 설정한 AI 서버로 자동 보내기) · 보고서 인쇄/Word |
| 공정 설정 | 공정 순서·이름·담당 인원·표준 공수·작업 요점·품질/안전 주의, 이름을 바꾸면 측정 기록도 함께 바뀜 |
| 설정 | 기본값(가용시간·목표 대수·인원·달성률 목표·제품 이름), AI 연결(OpenAI 호환 주소·모델·본인 키, 기억은 선택), JSON 백업, 샘플, 모두 지우기 |

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음)
- 샘플 파일 다시 만들기: `node scripts/make-samples.js` → `samples/` 3개
- 기획서 Word 다시 만들기: `python3 scripts/make-docx.py` (python-docx 필요)
- 브라우저 확인(선택): `PLAYWRIGHT=<playwright 경로> node scripts/browser-check.cjs` — 화면 12개 × 1280·390px 가로 넘침, 스톱워치, 엑셀 가져오기, 콘솔 오류

## 1단계 구현 범위

| 요청(기대 산출물) | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| 가용시간 대비 목표·실제 대수, 달성률 관리표 | 완료 | 일·주·월, 90% 선. 가용시간 정의는 확인 필요(기획서 10장 6번) |
| 공정별 작업시간 분석표와 병목공정 개선안 | 완료 | 측정 기반 사이클타임 vs 택트타임. 개선안 문장은 AI 반자동 |
| 작업 순서 및 인원 배분 개선안 | 완료(시뮬레이터) | 작업을 인원끼리 나눌 수 있다고 보는 모델. 한 사람만 할 수 있는 작업·선후 관계는 2단계 |
| 개선 전·후 생산량과 손실시간 비교표 | 완료 | 기간 두 개 |
| 제작 단가 절감 효과 분석표 | 완료(입력값 기준) | 대당 투입공수 × 임률 + 기타 원가. 회사 원가 계산 방식 확인 후 맞춤(10장 4번) |
| 표준작업서 | 초안 | 공정 설정의 메모로 만들고 AI 로 문장 다듬기. 현장 확인 후 사용 |
| 팀 공유 | 2단계 | 지금은 브라우저 저장 + JSON 백업 |
