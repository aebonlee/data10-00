# data10-13 · 불량 제품 파악

공유폴더의 수기 검사표 PDF 를 검사 예정 목록과 대조해 업로드 누락을 찾고, 검사표를 보며 값을 옮기거나(AI 반자동 판독) 스펙 기준표로 합불을 판정해 불합격 리스트 · 검사 누락 리스트 · 월별 불량률을 만드는 브라우저 도구

| 항목 | 내용 |
|---|---|
| 제출자 | 구민채 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-10-21) — https://aebonlee.github.io/data10-13/ |
| 다음 개발 | 2단계 — 실제 검사표 견본으로 양식(시료 수 · 여러 쪽) 맞추기, 손글씨 판독 정확도 측정(지금의 합불 엑셀을 정답으로), 사내 허용 AI 연결, 공유폴더 정기 점검 |

> 과제는 패들릿으로 접수했습니다. 실제 검사표는 아직 받지 않았고(기획서 10장 ①), 샘플은 직접 만든 **가상 검사표**입니다. 소속 회사명은 공개 리포에 두지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-13/**

처음 열면 **가상 샘플이 바로 들어가** ① 업로드 점검 화면이 나옵니다 — 검사 예정 33로트(2026년 8~10월), 손글씨처럼 그린 검사표 PDF 32장, 스펙 기준표 3품번 13항목. 8~9월 검사표는 이미 옮긴 것으로, 10월은 「판독 대기」로 두었습니다.
② 판독에서 10월 검사표를 열어 값을 옮겨 보세요. 「AI 로 읽기」 → 「가상 AI 답 예시 넣기(샘플 전용)」 → 「답 읽어 칸 채우기」 로 AI 반자동 판독 흐름도 키 없이 체험할 수 있습니다.

샘플에는 이런 것을 일부러 넣었습니다 — 업로드 누락 3로트, 스캔 기본 이름으로 올라와 로트를 모르는 파일 1개(판독하며 로트를 적으면 짝이 맞음), 같은 로트를 두 번 올린 것, 이름 규칙과 다른 파일, 예정 밖(7월) 파일, 하우징 외경 상한 초과(9월부터 위로 밀림), 축 지름 하한 미달, 외관 NG, 단위를 붙여 적은 값(52.06mm), 상한과 똑같은 값(8.10 — 합격), 쉼표 소수점(3,05), 빈 칸, 번진 글씨(25?.3).

실제로 쓸 때는 설정에서 「모든 자료 지우기」 후 자료 넣기에서 ① 검사 예정 목록 엑셀 ② 스펙 기준표 엑셀 ③ 검사표 PDF(여러 개 · 폴더째)를 넣습니다. 열 이름이 조금 달라도 찾고, 못 찾은 열은 화면에서 골라 연결합니다. 파일은 서버로 보내지 않고 이 브라우저 안에서만 읽고 저장합니다(PDF 는 IndexedDB).

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS, PDF 는 `vendor/pdfjs` 의 pdf.js).

| 화면 | 하는 일 |
|---|---|
| 자료 넣기 | 검사 예정 목록 · 스펙 기준표 엑셀(제목 줄 아래 머리행 자동 인식, 열 연결 확인/수정, 합계 줄 제외, 품번이 첫 줄에만 있는 기준표, 기준값 ± 공차 → 하한 · 상한) · 검사표 PDF 여러 개 · 폴더째 · 끌어 놓기(같은 파일은 건너뜀) · **PDF 없이 파일 이름 목록만 붙여 넣기**(업로드 점검만) |
| ① 업로드 점검 | 파일 이름 규칙(`{품번}_{로트}_{날짜}` 처럼 설정, 날짜 20260907 · 2026-09-07 · 260907) → 예정 로트와 짝(규칙이 어긋나도 이름 안의 로트로) · 업로드 누락 · 중복 · 이름 어긋남 · 예정에 없는 파일 · 로트별 상태 거르기 |
| ② 판독 | 왼쪽 검사표 그림(크게 보기 · 여러 쪽), 오른쪽 항목 칸 — **적는 즉시 항목 · 로트 합불**, Enter 로 다음 칸, 「판독 완료 · 다음」 은 다음 대기 파일로 · 품번 · 로트 · 검사일 고치기 · **AI 반자동 판독**: 가릴 영역(검사자 서명 칸 등)을 흰색으로 덮은 그림 받기 · 복사 → 프롬프트 복사 → 답(JSON) 붙여 넣기 → 칸 채우기(확신 낮은 칸은 노랑), 선택: 본인 키로 그림과 함께 자동 보내기 · 가릴 영역 끌어 그리기 |
| ③ 합불 결과 | **불합격 제품 리스트**(벗어난 항목 · 기준 · 적힌 값) · **검사 누락 리스트**(업로드 누락 · 판독 대기 · 검사 항목 누락 · 판독 확인 필요) · 월별 요약(불합격률 · 업로드율) · 품번별 · 항목별(경계 근처 포함) · 엑셀(8개 시트) |
| ④ AI 요약 | 계산된 숫자만 담은 보고용 프롬프트 — **품번은 「제품1」 같은 별칭으로 가림(기본)**, 답의 별칭은 원래 품번으로 되돌림 |
| ⑤ 스펙 기준표 | 품번별 항목 · 하한 · 상한 · 단위 · 판정 방식(수치 · OK/NG) 고치기 · 줄 더하기 · 엑셀로 |
| 설정 | 판정 규칙(경계값 포함 여부 · 빈 칸 처리 · 경계 근처 %), 파일 이름 규칙, 가릴 영역, AI 연결(OpenAI 호환 주소 · 모델 · 본인 키, 기억은 선택), JSON 백업 · 모두 지우기 |

**판정 규칙(기본값 — 기획서 10장 ④ 답을 받으면 맞춤)**: 한 항목이라도 하한 · 상한을 벗어나면 불합격(빈 칸이 함께 있어도) · 기준과 같은 값은 합격 · 빈 칸이 있으면 보류(검사 항목 누락) · 못 읽은 칸(「?」 · 단위 종류가 다름)은 보류 · mm/cm/μm, g/kg 은 기준 단위로 바꿔 비교. 값은 「적힌 그대로」 저장하고 매번 다시 판정하므로, 기준표나 규칙을 고치면 지난 판정도 새 기준으로 바뀝니다.

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음, 27개)
- **판 올리기(고칠 때마다)**: `node scripts/bump-version.mjs 2026-10-28.1` — index.html 의 모든 js·css `?v=` · logic.js · app.js 를 같은 값으로. 브라우저가 옛 파일과 새 파일을 섞어 쓰지 않게 하고, 섞이면 화면이 「새 판이 나왔습니다 — 새로고침(Ctrl+F5)」로 멈춥니다. `--check` 로 같은지만 봅니다(로직 테스트도 봄)
- 브라우저 점검(선택): `PLAYWRIGHT_CORE=<playwright-core 경로> node scripts/check-browser.mjs` — 주요 흐름 + 4가지 폭 × 7화면 가로 넘침(`BREAK=1` 이면 점검기가 넘침을 잡는지 확인)
- 샘플 다시 만들기: `python3 scripts/make-samples.py` (reportlab · openpyxl, 양식 글자는 나눔고딕) → `samples/` 엑셀 2개 · `samples/공유폴더_샘플/*.pdf` 32개 · `js/sample-data.js` · `js/sample-pdfs.js`
- 기획서 Word 다시 만들기: `python3 scripts/make-docx.py` (python-docx)

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| 업로드 누락 | 완료 | 검사 예정 목록과 파일 이름 대조, 중복 · 이름 어긋남 · 예정 밖 파일. 무엇과 대조할지(예정 목록의 출처)는 확인 대기(10장 ②) |
| 검사 누락 | 완료 | 판독 대기 · 검사표 빈 칸 · 못 읽은 칸을 「검사 누락 리스트」 로 |
| 불합격 제품 리스트 | 완료 | 스펙 기준표로 항목 · 로트 판정, 엑셀. 판정 규칙은 확인 대기(10장 ④) |
| 수기 PDF 분석 | 일부(반자동) | 손글씨는 이 도구가 직접 읽지 못합니다. 빠른 판독 화면 + AI 반자동 판독(사람 확인 필수). 자동 인식 정확도는 견본으로 잰 뒤 2단계 |
| 합불 엑셀 리스트 정리 | 완료 | 판독하면 합불 · 리스트 · 월별 요약이 함께 나옴(엑셀 8개 시트) |
| 공유폴더 자동 점검 · 알림 | 2단계 | 지금은 PDF 또는 파일 이름 목록을 넣어서 점검 |
