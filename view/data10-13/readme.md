# data10-13 · 불량 제품 파악

공유폴더의 수기 검사표(「자주 검사 CHECK SHEET」 PDF)에서 모델 · 품번 · 호기와 측정값을 읽고(글자 층은 자동, 스캔은 사람 · AI 반자동), 검사표에 적힌 공차로 호기마다 합불을 판정해 **출하일정과 맞춰 「출하 예정인데 검사표 없음 · 불합격 · 미판정」 리스트**를 만드는 브라우저 도구

> 2차는 수강생 답(10-27, 기획서 10장)대로 바꿨습니다 — 양식은 「자주 검사 CHECK SHEET」(한 장에 호기 여럿 · LH/RH 줄), 파일 이름 규칙 없음, 규격은 검사표에 적힘, 한 칸이라도 벗어나면 불합격, 검사 목록은 출하일정. 받은 견본은 칸 배치만 본떴고 **샘플은 지어낸 검사표**입니다(MODEL-A100 · B200, 품번 QA-…). 소속 회사명 · 실제 모델 · 품번은 리포에 두지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-13/**

처음 열면 **가상 샘플이 바로 들어가** ① 출하 대조 화면이 나옵니다 — 출하일정 13대, 검사표 6장(글자 층 4장은 넣자마자 자동으로 읽음 · 스캔 그림 2장), 기준일 2026-10-28.
② 판독에서 스캔 검사표를 열어 보세요. 「모델 상부 #314504」 는 파일 이름에서 모델 · 호기를 짐작해 노란 칸으로 두고 같은 모델 검사표의 항목으로 칸을 미리 만듭니다. 「AI 로 읽기」 → 「가상 AI 답 예시 넣기(샘플 전용)」 → 「답 읽어 칸 채우기」 로 AI 반자동 흐름도 키 없이 체험할 수 있습니다. 「1013~1015 작업」 은 이름에 아무 단서가 없어 품번 · 호기를 직접 적는 예입니다.

샘플에 일부러 넣은 것 — 비대칭 공차 상한 초과(48 +1.0/-0.5 에 49.3 → 불합격, 문제점 칸 「재가공 후 재측정」), 상한과 같은 값(2746 · 421 → 합격), 빈 칸(→ 보류), 값 없이 체크(V)만 한 칸, 육안 NG(외관), 「1.5 MAX」 항목, 모델 칸에 두 모델(「A / A-E」), 품번이 빈 출하 줄(모델 + 호기로 짝), 숫자로 적힌 호기 칸, 호기 범위(315015~315016), 출하일정에 없는 호기, 표 왼쪽 도면의 LH/RH · 치수 글자(값으로 읽지 않아야 함), 결재 칸 · 검사자 서명(AI 에 보낼 그림에서 가림).

실제로 쓸 때는 설정에서 「모든 자료 지우기」 후 자료 넣기에서 ① 출하일정 엑셀 ② 검사표 PDF(여러 개 · 폴더째)를 넣습니다. 열 이름이 조금 달라도 찾고, 못 찾은 열은 화면에서 골라 연결합니다. 파일은 서버로 보내지 않고 이 브라우저 안에서만 읽고 저장합니다(PDF 는 IndexedDB). AI 는 기본으로 아무 데도 보내지 않습니다(프롬프트 복사 · 답 붙여 넣기, 자동 보내기는 설정한 경우에만).

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS, PDF 는 `vendor/pdfjs` 의 pdf.js).

| 화면 | 하는 일 |
|---|---|
| 자료 넣기 | 출하일정 엑셀(출하일 · 모델 · 품번 · 호기 · 수량 — 제목 줄 아래 머리행 자동, 열 연결 확인/수정, 「314498~314500」 · 「314498, 314499」 펼침) · 검사표 PDF 여러 개 · 폴더째 · 끌어 놓기(같은 파일은 건너뜀, 넣는 즉시 글자 층 읽기) · 스펙 덮어쓰기 표(선택) |
| ① 출하 대조 | 출하일정의 호기마다 **품번 + 호기**(없거나 다르면 **모델 + 호기**)로 검사 기록과 짝 → **검사표 없음 · 불합격 · 미판정**(판독 대기 · 보류) 목록을 출하일 순 · 남은 날(D-n)로, 기준일 바꾸기 · **식별이 필요한 검사표**(파일 이름으로만 / 식별 안 됨) · 출하일정에 없는 검사 |
| ② 판독 | 왼쪽 검사표 그림(크게 보기), 오른쪽 머리 칸(작성일 · 제작 공정명 · 모델명 · 품번 · 품명 · 관리 번호)과 **항목 줄 × 호기 열 입력 표**(LH/RH · FR/RE 줄 따로, 문제점 칸) — 적는 즉시 칸 색과 호기 판정, Enter 로 아래 칸 · 같은 품번(모델) 검사표의 항목으로 미리 채움 · 검사 항목 고치기 · 호기 열 더하기 · **AI 반자동**(가릴 영역을 흰색으로 덮은 그림 받기 · 복사 → 프롬프트 복사 → 답(JSON) 붙여 넣기 → 칸 채우기, 확신 낮은 칸은 노랑, 선택: 본인 키로 그림과 함께 자동 보내기) |
| ③ 검사 결과 | **불합격 리스트**(출하일 · 호기 · No · 구분 · 검사 항목 · 기준 · 적힌 값 · 문제점) · 호기별 결과 · 품번별 · 칸별(경계 근처 포함) · **엑셀 8개 시트**(불합격_리스트 · 검사_결과 · 측정값_전체 · 출하_대조 · 검사표_없음 · 미판정 · 식별_필요 · 출하일정에_없는_검사) |
| ④ AI 요약 | 계산된 숫자만 담은 보고용 프롬프트 — **품번 · 모델은 「제품1」 「모델1」 별칭으로 가림(기본)**, 답의 별칭은 원래 이름으로 되돌림 |
| ⑤ 스펙 | 검사표 글자에서 읽은 규격과 실제로 쓰는 기준 · **덮어쓰기 표**(품번 + 검사 항목 또는 No · 하한 · 상한) |
| 설정 | 판정 규칙(경계값 · 빈 칸 · 체크만 한 칸 · 경계 근처 %), 가릴 영역, AI 연결(OpenAI 호환 주소 · 모델 · 본인 키, 기억은 선택), JSON 백업 · 모두 지우기 |

**규격 읽기**: 검사 항목 칸의 「420±1」 「2740 ± 6 mm」 「48 +1.0/-0.5」 「1.5 MAX」 「MAX 0.03」 「MIN 40」 「40 이상」 「8.00~8.10」 → 하한 · 상한. 단위는 따지지 않고 숫자끼리 비교합니다. 육안 항목(측정기 「육안」 · 외관)은 OK/NG.

**판정 규칙(10장 ④)**: 호기마다, 한 칸이라도 하한 · 상한을 벗어나면 불합격(빈 칸이 함께 있어도) · 기준과 같은 값은 합격 · 육안 NG 는 불합격 · 빈 칸 · 못 읽은 칸(「?」) · 규격을 못 읽은 항목은 보류(미판정) · 값 없이 체크(V · ✓)만 한 칸은 합격(설정에서 보류로). 값은 「적힌 그대로」 저장하고 매번 다시 판정하므로, 덮어쓰기 표나 규칙을 고치면 지난 판정도 새 기준으로 바뀝니다.

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음, 26개 — 글자 층은 vendor 의 pdf.js 로 샘플 PDF 를 직접 읽음)
- **판 올리기(고칠 때마다)**: `node scripts/bump-version.mjs 2026-10-28.1` — index.html 의 모든 js·css `?v=` · logic.js · app.js 를 같은 값으로. 브라우저가 옛 파일과 새 파일을 섞어 쓰지 않게 하고, 섞이면 화면이 「새 판이 나왔습니다 — 새로고침(Ctrl+F5)」로 멈춥니다. `--check` 로 같은지만 봅니다(로직 테스트도 봄)
- 브라우저 점검(선택): `PLAYWRIGHT_CORE=<playwright-core 경로> node scripts/check-browser.mjs` — 2차 주요 흐름 + 4가지 폭 × 7화면 가로 넘침 + 바깥 주소 요청 0(`BREAK=1` 이면 점검기가 넘침을 잡는지 확인)
- 샘플 다시 만들기: `python3 scripts/make-samples.py` (reportlab · openpyxl · Pillow · poppler 의 pdftoppm, 양식 글자는 나눔고딕) → `samples/출하일정_샘플.xlsx` · `samples/공유폴더_샘플/*.pdf` 6장 · `js/sample-data.js` · `js/sample-pdfs.js`
- 기획서 Word 다시 만들기: `python3 scripts/make-docx.py` (python-docx)
