# data10-14 · 재고실사 비효율 개선 (재고실사 Start-End)

ERP 재고 엑셀과 창고 배정표로 기준 일자·시각이 박힌 재고실사 기록서(작업지시서 · SharePoint 취합 파일)를 만들고, 휴대폰이나 SharePoint 엑셀로 실물수량·사유(차이가 있으면 필수)·사진을 남기고, 여러 사람의 결과를 합쳐 차이대사·창고별·창고위치(사내/사외)별 분석과 버전·원천 기록 연결이 있는 결과 보고서를 만드는 브라우저 도구

|---|---|
| 제출자 | 이미란 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계 개발 완료 · **2차 반영 완료 (2026-10-21)** — https://aebonlee.github.io/data10-14/ |
| 다음 개발 | 보고서(pptx) 목차 받으면 보고서 양식 맞추기 · 2단계 실시간 취합(SharePoint 목록 + Power Automate, 또는 공유 DB) · 사진 비공개 저장소 |

> 과제는 패들릿으로 접수했습니다. **2차 반영(2026-10-21)**: 수강생이 보낸 ERP 재고 엑셀 견본 · 창고 배정표 · 기록서 견본의 **모양(열 이름 · 줄 배치)** 에 맞췄습니다. 샘플은 그 모양을 그대로 본뜬 **가상 값**이고, 실제 자재번호 · 창고명 · 사람 이름 · 금액은 리포에 넣지 않았습니다. 소속 회사명도 공개 리포에 두지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-14/**

처음 열면 「작업지시」 화면입니다. **「가상 샘플로 시작」** 을 누르면 가상 ERP 재고 248품목(창고 6곳)에 창고 배정표를 적용한 240품목(시험실창고 8품목은 실사인원 0 이라 제외), 실사자 5명의 배정과 현장 기록이 들어가고 진행 현황으로 넘어갑니다.
샘플에는 일부러 심어 둔 것이 있습니다 — 소모품창고 「입출고 누락」, 부품창고 B 구역 「위치 이동·분산」(부품창고는 실사자 2명이 반씩), 제품창고 라벨이 바뀐 짝, 두 사람이 따로 센 수량이 다른 충돌 2건, 같은 사람이 다시 센 정정 2건, 외주창고(사외) 진행 지연, 목록에 없는 잔재 2건, 이번 실사 제외 창고 1곳. 실사자E 가 SharePoint 취합 파일의 자기 시트에 적은 40줄(과 실사자C 가 전체 시트에 적은 2줄)은 ③ 취합에서 「합치기 체험」으로 들어옵니다.

실제로 쓸 때의 흐름입니다(지금 쓰는 SharePoint 취합 방식을 그대로 살림). 파일과 기록은 서버로 보내지 않고 그 기기의 브라우저 안에서만 읽고 저장합니다.

1. **사무실** — ① 작업지시에서 ERP 재고 엑셀을 올리고 기준 일자·시각을 넣어 작업지시를 만든 뒤, **창고 배정표 엑셀**(저장위치 · 저장위치명 · 창고위치 · 실사인원 · 담당팀 · 담당자 · 실사자 · 비고)을 올립니다. 실사인원 0 창고는 빠지고, 실사자가 여럿이면 그 창고를 Location 순서로 사람 수만큼 나눕니다. 같은 엑셀 파일에 ERP 시트와 배정표 시트가 함께 있으면 한 번에 적용됩니다.
2. 「기록서 엑셀 (SharePoint 취합용)」을 받아 **SharePoint 에 올립니다.** ERP 원래 열 뒤에 담당자 · 실사자 · 실물수량 · 차이수량(수식) · 사유 · 특이사항 · 확인자 · 확인시각이 붙어 있고, 실사자별 시트도 있습니다.
3. **현장** — 각자 자기 이름 시트(또는 전체 시트의 자기 줄)에 실물수량을 적습니다. 휴대폰으로 하려면 같은 주소에 기록서 엑셀을 넣고 ② 현장 입력에서 적은 뒤 「결과 엑셀 받기(기록서 양식)」로 보내면 됩니다(사진까지 보내려면 결과 파일 JSON).
4. **사무실** — 다 채운 SharePoint 파일(과 휴대폰 결과)을 ③ 취합에 넣고, ④ 차이대사 · ⑤ 분석 · ⑥ 보고서로 이어 갑니다. 같은 파일을 여러 번 넣어도 새로 적은 줄만 들어갑니다.

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS).

## 구현 범위 (1단계 + 2차 반영)

| 요청 | 상태 | 한 것 / 남은 것 |
|---|---|---|
| ERP 엑셀 업로드로 작업지시 출발 (01) | 완료 · **견본 반영** | 견본 열(저장위치 · 저장위치명 · 창고위치 · Location · 수량)로 바로 읽음, 추가 열 보존, 기준 일자·시각 필수, 기록서 엑셀·인쇄 |
| 작업배정 시스템화 | 완료 · **배정표 반영** | 창고 배정표(실사인원 0 제외 · 실사자 수만큼 나눔 · 담당자), 이름 목록 자동 배정, 지시서 버전 |
| 휴대폰 현장 입력 (02·04) | 완료 | 실물수량 · 사유(차이가 있으면 필수, 목록은 설정) · 특이사항 · 사진(필요할 때) · 확인 시각 · 작성자 |
| 차이 확인 (03) | 완료 · **답 ③ 반영** | 기본 허용 0(차이가 있으면 모두 사유), 차이율·금액 허용은 선택 |
| 취합 (05) | 완료 · **답 ⑤ 반영** | SharePoint 취합 엑셀 1개(자기 시트 · 자기 줄) 내보내기 · 다시 합치기. 실시간 공유는 2단계 — SharePoint 목록 + Power Automate 또는 공유 DB 초안 `supabase/schema.sql`(앱 미연결) |
| 창고별·자재유형별·자재타입별 BI | 완료 | 창고별 · 창고위치(사내/사외)별 · 실사자별 · 사유별 · 시간대별. 견본 ERP 에는 자재유형·자재타입 열이 없어 열이 추가되면 자동으로 보임 |
| 최종 보고서 (06) | 완료(엑셀·인쇄·Word) | 버전·원천 기록 연결·제외 창고. 회사 pptx 목차는 수강생 확인 대기(10장 ④) |
