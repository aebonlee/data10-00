# data10-12 · 각종 Certification(선급 Type Approval) 관리방안 개선

인증 관리대장 엑셀을 넣으면 만료일에서 거꾸로 갱신 일정(준비·신청·기관 심사·피드백·발급)을 세워 간트·상태 신호로 보여 주고, 영업·품질·개발 부서별 알림 메일 초안, 업무흐름도(R/R), 이전/신규 인증서 변경 비교와 보고서를 만들며, 「모델-형식」별로 인증 이력(지난 인증서 · 중지된 인증)과 인증서 PDF 를 모아 보는 브라우저 도구

| 항목 | 내용 |
|---|---|
| 제출자 | 윤한산 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-10-21) · **2차 반영 (2026-10-27)** — 인증 이력 · 중지된 인증 · 인증서 PDF · 모델-형식 묶음 — https://aebonlee.github.io/data10-12/ |
| 다음 개발 | 2단계 — 실제 관리대장·인증서로 열 연결과 리드타임 맞추기, 알림 자동 발송(Make·Power Automate), 메일에서 진행 날짜 뽑기, 실제 리드타임 학습 |

> 과제는 패들릿으로 접수했습니다. 실제 관리대장·인증서는 아직 받지 않았고(기획서 10장 ①②), 샘플은 공개된 선급 이름과 지어낸 제품·모델·인증서 번호·담당자로 만든 **가상 값**입니다. 소속 회사명은 공개 리포에 두지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-12/**

처음 열면 「데이터 가져오기」 화면입니다. **「샘플로 시작」** 을 누르면 가상 관리대장 22건(운영 중) + 「인증 이력」 시트(지난 인증서 7줄 · 중지·종료 인증 3건) + 가상 인증서 PDF 6장 + 비교용 인증서 2장이 들어가고 대시보드로 넘어갑니다.
샘플의 만료일은 **여는 날(오늘)** 기준으로 배치해, 언제 열어도 운영 중 22건에서 만료 2 · 지연 2 · 임박 3 · 배포 필요 1 · 준비 시작/진행 4 · 준비 예정 1 · 정상 8 · 완료 1 이 보입니다.

**1단계에서 넣어 둔 데이터는 그대로 남습니다.** 2차 화면을 처음 열 때 저장 모양만 옮기고(모두 「운영 중」, 1단계에서 남긴 이력은 「갱신됨」), 값은 지우지 않습니다.
실제로 쓸 때는 관리대장 엑셀을 넣어 주세요. 열 이름이 조금 달라도 찾고, 못 찾은 열은 화면에서 골라 연결합니다. 파일은 서버로 보내지 않고 이 브라우저 안에서만 읽고 저장합니다.

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS, PDF 는 `vendor/` 의 pdf.js).

| 화면 | 하는 일 |
|---|---|
| 데이터 가져오기 | 관리대장 엑셀 여러 개 · 제목 줄 아래 머리행 자동 인식 · 열 이름 별칭(「선급」「유효기간」「Valid until」「인증서 No.」 …) · 열 연결 확인/수정 · 여러 날짜 표기(2027.3.15 · 15-Mar-2027 · 15.03.2027) · 같은 인증은 한 행 |
| ① 대시보드 | 상태 신호 타일(만료·지연·임박·배포 필요·준비 시작·준비 예정·정상·완료), 지금 할 일, 앞으로 12개월 만료·준비 시작 건수, 인증기관별 |
| ② 갱신 타임라인 | 인증별 간트 — 준비 → 기관 심사 → 피드백 대응 → 발급 처리 → 여유, 만료일, 오늘 선 · 상태·기관·기간 거르기 · 일정 표 |
| ③ 관리대장 | 진행 단계·신청일·배포일 바꾸기, 한 건 추가·고치기(운영 상태·중지 사유·중지일 포함), **다음 주기로 넘기기**(이전 번호·날짜·PDF 는 이력), 「운영 중만」 「중지·종료」 거르기 · 모델-형식 순, 엑셀(계획 날짜 + 「인증 이력」 시트 — 그대로 다시 넣을 수 있음) |
| ③-2 모델별 이력 (2차) | **「모델-형식」 묶음**(띄어쓰기·대소문자·하이픈 모양이 달라도 한 묶음) — 기관·종류별 인증, 지금 + 지난 인증서 타임라인, **과거 이력 추가**, **중지·만료 종료·폐기**(사유·중지일 — 알림에서 빠지고 이력에 남음), **인증서 PDF** 붙이기·보기(화면 안 · 새 탭)·바꾸기·빼기 |
| ④ 알림 | **오늘 연락할 사람** — 인증마다 가장 최근의 끝나지 않은 일 하나, 부서별 메일 초안(메일 앱으로 열기·제목/본문 복사), 90일 안 다가오는 일 |
| ⑤ 업무흐름 · R/R | 단계표(RACI)를 고치면 부서별 줄 흐름도가 다시 그려짐 · SVG 내려받기 · RACI 규칙 점검 |
| ⑥ 인증서 비교 | 이전/신규 인증서(PDF 글자층·글 붙여 넣기) — 「항목: 값」 맞대기(내용 / 번호·날짜), 항목이 아닌 문장 차이, 낱말 단위 표시 · AI 요약 프롬프트(**회사명·메일·전화·인증서 번호 가림**) · 답 되돌리기 |
| ⑦ 보고서 | 현황 보고 · 변경 내용 보고 — 인쇄/PDF, Word, 엑셀 |
| 설정 | 기준일, 알림 시점(준비 예정·임박·유예·미리 보기), **인증 종류별 리드타임**, 기관별 추가 일수, 부서 메일·알림 받는 부서, AI 연결(OpenAI 호환 주소·모델·본인 키, 기억은 선택), JSON 백업(**PDF 포함** / PDF 빼고) · 불러오기 |

**과거 이력·중지된 인증을 엑셀로 넣을 때**: 관리대장 파일에 이름에 「이력」이 든 시트(예: 「인증 이력」)를 더하고 관리대장과 같은 열(모델-형식 · 인증기관 · 인증 종류 · 인증서 번호 · 발급일 · 만료일)에 **이력 상태**(갱신됨 · 중지 · 만료 종료 · 폐기) · **중지 사유** · **중지일**을 적어 주세요. 같은 모델-형식 · 기관 · 종류의 인증에 이력으로 붙고, 붙일 인증이 없으면 중지·종료 인증 한 건으로 들어갑니다. 샘플 `samples/인증_관리대장_샘플.xlsx` 의 「인증 이력」 시트가 그 모양입니다.

**인증서 PDF** 는 서버로 보내지 않고 이 브라우저(IndexedDB)에만 둡니다. 한 장 15MB 까지. 다른 PC 로 옮길 때는 「JSON 백업(PDF 포함)」을 써 주세요.

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음, 55개)
- 브라우저 점검(선택): `PLAYWRIGHT_CORE=/경로/node_modules/playwright-core node scripts/check-browser.mjs`
- 샘플 파일 다시 만들기: `node scripts/make-samples.js [기준일]` → `samples/` 관리대장 xlsx(관리대장 + 인증 이력 시트) + 인증서 txt·pdf + 첨부 시험용 pdf
- 기획서 Word 다시 만들기: `python3 scripts/make-docx.py` (python-docx 필요)

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| 1) 업무흐름도(관련부서 R/R 포함) | 완료 | 단계표(RACI) → 부서별 줄 흐름도 SVG, R/R 표. 실제 단계·역할은 확인 대기(기획서 10장 ④) |
| 2) 실시간 관리대장 비주얼화(준비·피드백 감안 Lead-Time) | 완료 | 인증 종류별 리드타임으로 만료일 역산, 간트·상태 신호·대시보드. 실제 소요 기간은 확인 대기(10장 ③) |
| 3) 영업·품질·개발 Alert | 일부(초안까지) | 오늘 연락할 목록, 부서별 메일 초안(mailto·복사). 자동 발송은 2단계(10장 ⑤) |
| 4) 이전/신규 인증서 변경 요약·보고서 | 완료(규칙 + 반자동 AI) | 항목·문장 비교, AI 요약 프롬프트(이름 가림), 보고서. 스캔본 OCR 은 2단계 |
| 담당자 e-Mail 활용 | 2단계 | 메일에서 신청·피드백 날짜 뽑기 |
| 팀 공유·동기화 | 2단계 | 지금은 브라우저 저장 + JSON 백업(PDF 포함 가능) |
