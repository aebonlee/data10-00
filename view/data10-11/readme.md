# data10-11 · Deep drawing press 제품 불량 최소화

Deep drawing press 작업일보 엑셀을 여러 달 쌓아 일별·월별·금형·소재별 작업량 대비 불량률, 4M·계절별 「불량이 몰린 조건」, 금형 보수 전후 비교, AI 프롬프트(사실만·이름 가림)와 보고서 초안을 만드는 브라우저 도구

| 항목 | 내용 |
|---|---|
| 제출자 | 이성헌 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-10-20) — https://aebonlee.github.io/data10-11/ |
| 다음 개발 | 2단계 — 실제 작업일보로 열 연결·정상 압력 범위 확정, 불량 유형·소재 로트 연계, 금형 보수 시점 예측(보수 이력이 쌓인 뒤), 팀 공유 |

> 과제는 패들릿으로 접수했습니다. 실제 작업일보는 아직 받지 않았고(기획서 10장 ①), 샘플은 제출 글의 항목대로 새로 만든 **가상 값**입니다. 소속 회사명은 공개 리포에 두지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-11/**

처음 열면 「데이터 가져오기」 화면입니다. **「샘플 12개월로 시작」** 을 누르면 가상 작업일보 12개월(1,130행)과 가상 금형 보수 이력이 들어가고 ③ 4M·계절 분석 화면으로 넘어갑니다.
샘플에는 세 가지 패턴을 일부러 심어 두었습니다 — 금형 DIE-B01 마모(보수 후 누적 작업량이 늘수록 불량률 상승, 보수하면 떨어짐), 겨울 소재사B Crack 증가, 쿠션 압력 65 이상 Crack 증가. Main 압력은 불량과 관계없게 만든 대조군입니다.
실제로 쓸 때는 작업일보 엑셀을 **6개월~1년 치 한꺼번에**(파일을 모두 고르거나 「폴더째 고르기」) 넣어 주세요. 열 이름이 조금 달라도 찾고, 못 찾은 열은 화면에서 골라 연결합니다. 파일은 서버로 보내지 않고 이 브라우저 안에서만 읽고 저장합니다.

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS).

| 화면 | 하는 일 |
|---|---|
| 데이터 가져오기 | 작업일보 엑셀 여러 개·폴더째 · 차례로 읽기(진행 표시) · 제목 줄 아래 머리행 자동 인식(두 줄 머리 포함) · 열 이름 별칭·단위 무시(「일자」「금형번호」「Main 압력(bar)」 …) · 열 연결 확인/수정(머리행이 같은 파일에 함께 적용) · 「합계·소계」 줄 제외 · 불량>작업 등 행 점검 · 같은 파일 두 번 넣어도 한 번만 · 빠진 달 점검 |
| ① 불량률 추이 | 월별·일별 작업량 대비 불량률(작업량 가중) — 목표 2% 선·지금 수준 5% 선, 월별 작업수량, 목표 초과 달, 목표까지 줄일 불량 수, 불량 유형별(칸이 있을 때) |
| ② 항목별 불량률 | 금형·소재 메이커·소재규격·작업모델·작업자(·소재 로트)별 표와 가로 막대 — 불량률, 전체 대비 배수, 「기대보다 많은 불량」, 불량 비중, **표본 적음** 표시 · 금형 × 소재 메이커 교차표 · 엑셀(모든 표) |
| ③ 4M · 계절 분석 | **불량이 몰린 조건** — 한 조건·두 조건 조합을 근거 숫자와 함께(표본·배수·95% 하한 기준, 다른 조건과의 「겹침」 표시) · 계절 × 소재 메이커 교차표 · Man·Machine·Material·Method·계절별 구간 그래프(Main·쿠션 압력 구간, 정상 범위 아래·안·위, 금형 누적 작업량) · 금형 보수 전후 비교와 금형별 누적 작업량 곡선 |
| ④ AI 프롬프트 | 계산된 사실만 담은 프롬프트 — **금형·모델·소재 메이커·작업자 이름은 「금형1」 같은 별칭으로 가림(기본)**, 대응표는 이 PC 에만, AI 답은 원래 이름으로 되돌림(복사·붙여 넣기, 선택: 설정한 AI 서버로 자동 보내기) |
| ⑤ 보고서 | 총괄·월별·금형/소재별·불량이 몰린 조건·금형 보수·AI 의견 — 인쇄/PDF, Word, 엑셀, 글자 복사 |
| 설정 | 목표·지금 불량률, Main·쿠션 압력 정상 범위, 표본·배수 기준, **금형 보수·교체 이력**(직접 넣기·엑셀에서 붙여 넣기, 보수 전후 불량률), AI 연결(OpenAI 호환 주소·모델·본인 키, 기억은 선택), JSON 백업 |

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음)
- 샘플 파일 다시 만들기: `node scripts/make-samples.js` → `samples/` 작업일보 12개 + 금형 보수이력 1개
- 기획서 Word 다시 만들기: `python3 scripts/make-docx.py` (python-docx 필요)

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| ① 작업 일별/월별 작업량 대비 불량률 분석표 | 완료 | 작업량 가중 불량률, 목표선, 엑셀 내보내기 |
| ② 금형/소재별 작업량 대비 불량률 분석표 | 완료 | 금형·소재 메이커·소재규격(+작업모델·작업자), 표본 적음 표시, 금형 × 메이커 교차표 |
| 계절별 4M 근거로 Crack 원인 추측 데이터 | 완료(규칙 + 반자동 AI) | 「불량이 몰린 조건」을 근거 숫자와 함께 찾고, AI 는 그 사실만으로 「추정」을 정리. 원인 확정은 현장 확인 몫 |
| 소재 문제 / 프레스 압력 문제 | 완료(구간 분석) | 압력 구간·정상 범위 아래·안·위. 실제 정상 범위 값은 확인 대기(기획서 10장 ⑤) |
| 금형 보수 시점 예측 | 일부 | 보수 전후 비교 + 「보수 후 누적 작업량이 이 구간부터 불량률이 올랐다」 참고값. 예측은 보수 이력이 쌓인 뒤 2단계 |
| 불량 유형(Crack 외) | 준비됨 | 유형 칸이 있으면 유형별로 봄. 실제 기록 여부 확인 대기(10장 ②) |
| 팀 공유·동기화 | 2단계 | 지금은 브라우저 저장 + JSON 백업 |
