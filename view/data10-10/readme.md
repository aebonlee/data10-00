# data10-10 · AI 기반 회의록 요약 도우미

회의 직후 메모장 · 워드로 적은 메모와 회의록 서식을 넣으면, 결정 사항과 Action Item(할 일 · 담당 · 기한)까지 서식 칸에 맞춰 정리하는 브라우저 도구(반자동 AI · 로컬 LLM · AI 없는 규칙 초안)

| 항목 | 내용 |
|---|---|
| 제출자 | 나선준 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-10-20) — https://aebonlee.github.io/data10-10/ |
| 다음 개발 | 2단계 — 실제 회의록 서식 · 메모 · 완성 회의록(정답 견본)으로 규칙과 프롬프트 맞추기, 회의 종류별 필수 항목 경고, 보안 기준에 맞춘 기본 방법(로컬 LLM) 정하기, 옛 워드(.doc) · 한글(.hwp) 읽기 |

> 과제는 패들릿으로 접수했습니다. 첨부 자료는 없어서 **메모 · 서식은 모두 가상 예시**입니다(사람 · 시료 · 과제 이름 모두 지어낸 것). 실제 메모를 받더라도 사내 문서라 이 리포에는 넣지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-10/**

처음 열면 「00 한눈에 보기」입니다. **예시 메모 3개** 중 하나를 누르면 「01 메모 → 회의록」에 메모와 맞는 서식이 들어갑니다. 「AI 없이(규칙 초안)」 탭의 **「규칙으로 초안 만들기」** 를 누르면 바로 회의록 편집 화면이 열립니다.
실제로 쓸 때는 ① 서식 고르기(우리 팀 워드 양식이 있으면 「04 서식 관리」에서 .docx 로 서식 만들기) → ② 메모 붙여 넣기 또는 .txt · .docx 고르기 → ③ 이름 가리기 확인 → ④ 세 가지 방법 중 하나로 정리 → 편집 · 내보내기 순서입니다.

내 PC 에서 열려면 ZIP 을 풀고 `index.html` 을 더블클릭합니다(설치 · 인터넷 필요 없음). 외부 CDN 을 부르지 않습니다(워드 읽기는 `vendor/` 의 JSZip).

### 정리하는 세 가지 방법

| 방법 | 메모가 가는 곳 | 하는 법 |
|---|---|---|
| 반자동(기본) | 사용자가 붙여 넣은 AI 한 곳 | 「프롬프트 복사」 → 회사가 허용한 AI 에 붙여 넣기 → 답을 붙여 넣고 「답으로 서식 채우기」. 이름 가리기를 켜 두면 「인물1」 처럼 가려서 보내고 답은 이름으로 되돌립니다 |
| 로컬 LLM 자동 보내기 | **내 PC 안**(Ollama · LM Studio) | 「05 설정」에서 서버 종류 → 모델 목록 불러오기 → 저장. 「설정한 AI 서버로」 탭에서 버튼 한 번 |
| AI 없이 규칙 초안 | 어디로도 안 감 | 「결정 · 확정 · 하기로」 줄 → 결정 사항, 담당(이름 · @이름 · 담당:)이나 기한(10/24 · 다음 주 금요일)이 붙은 할 일 줄 → Action Item, 「다음 회의」 줄 → 다음 회의. 문장 요약은 하지 않습니다 |

### 로컬 LLM 으로 쓰기 (사내 문서를 외부 AI 에 넣을 수 없을 때)

로컬 LLM 은 내 PC 에서 돌아가는 AI 입니다. 메모가 PC 밖으로 나가지 않습니다. 이 도구는 **OpenAI 호환 주소**(`…/v1/chat/completions`)로 보내므로 Ollama · LM Studio · 사내 LLM 서버 모두 같은 방법으로 붙습니다.

1. **설치** — [Ollama](https://ollama.com) 또는 [LM Studio](https://lmstudio.ai). 회사 PC 라면 설치 가능 여부를 IT 에 먼저 확인합니다.
2. **모델 받기** — 한국어를 잘 하는 모델을 받습니다. 예) `ollama pull qwen3:8b` (메모리 16GB 이상 권장, 8GB 면 더 작은 모델). LM Studio 는 화면에서 모델을 내려받고 Developer 화면에서 서버를 켭니다.
3. **도구를 파일로 열기** — ZIP 을 풀고 `index.html` 더블클릭(file://). 이렇게 열면 Ollama 는 따로 설정 없이 요청을 받습니다. LM Studio 는 서버 설정의 **「Enable CORS」** 를 켭니다.
4. **연결** — 「05 설정 → AI 연결 설정」에서 서버 종류를 고릅니다.
   - Ollama: `http://localhost:11434/v1`
   - LM Studio: `http://localhost:1234/v1`
   - 사내 LLM 서버: 담당 부서에서 받은 주소(보통 `…/v1` 로 끝남)
   「모델 목록 불러오기」 → 모델 고르기 → 「연결 확인」 → 「저장」. 로컬 LLM 은 키를 비워 둡니다.
5. **보내기** — 「01 메모 → 회의록」 4번의 「설정한 AI 서버로(로컬 LLM)」 탭 → 「설정한 AI 서버로 보내기」.

- 온라인 주소(https://aebonlee.github.io/…)에서도 크롬 · 엣지는 `localhost` 로 보낼 수 있지만, 그때는 Ollama 에 `OLLAMA_ORIGINS` 설정이 필요합니다. **파일로 여는 것이 가장 쉽습니다.**
- Qwen3 처럼 「생각하는 모드」가 있는 모델이 답 앞에 붙이는 `<think>…</think>` 는 도구가 떼고 답만 씁니다.
- 작은 모델은 담당 · 기한을 틀리기 쉽습니다. 편집 화면의 **「확인 필요」**(메모에 없는 담당 · 기한 · 결정)를 꼭 확인하세요.

| 화면 | 하는 일 |
|---|---|
| 00 한눈에 보기 | 흐름 4단계, 저장한 회의록 · 남은 할 일 · 기한 지남 · 3일 안 기한 수, 예시 메모 3개, 세 가지 방법 비교 |
| 01 메모 → 회의록 | ① 서식 고르기(칸 미리 보기) ② 메모 넣기(붙여 넣기 · .txt UTF-8/ANSI · .docx, 회의일) ③ 이름 가리기(이름 찾기 · 켜고 끄기 · 더하기 · 대응표 · 남은 이름 점검) ④ 정리하기 — 반자동 · 설정한 AI 서버(로컬 LLM) · AI 없이 규칙 초안. 작성 중 메모는 새로고침해도 남음 |
| 회의록 편집 | 칸별 편집(목록 칸은 한 줄 한 항목), Action Item 표(할 일 · 담당 · 기한 · 완료 · 더하기/지우기), **메모 근거 점검**(메모에 없는 담당 · 기한, 메모와 많이 다른 결정 · 할 일 문장), 메모 원문 대조, 저장 · Word(.doc) · 인쇄/PDF · 글 복사 · 지우기 |
| 02 회의록 목록 | 회의일 순, 찾기(회의명 · 내용 · 담당자), 할 일 남은 수 · 기한 지남 표시 |
| 03 Action Item | 모든 회의록의 할 일을 기한 순으로 — 남은 할 일 · 기한 지남 · 전체 · 완료, 담당자로 거르기, 「N일 지남 · 오늘 · N일 남음」, 완료 체크(그 회의록에 저장), 글 복사 |
| 04 서식 관리 | 기본 3종(일반 회의 · 시험·검증 결과 리뷰 · 일정 점검), 칸 이름 · 역할 · 모양 · 도움말 편집, 순서 바꾸기, 복사 · 기본값으로, **워드 양식(.docx) · 양식 글로 새 서식 만들기** |
| 05 설정 | AI 연결(OpenAI 호환 주소 · 모델 목록 · 본인 키 — 기억은 선택), 로컬 LLM 준비 안내, 늘 가릴 이름 · 가리기 기본값 · 메모 원문 저장 여부, 백업(.json) 받기 · 불러오기 · 모두 지우기 |

- 로직 테스트: `node test/logic.test.mjs` (24개) · `node test/ai-endpoint.test.mjs` (13개) — 의존성 없음
- 화면 점검(개발용): `PLAYWRIGHT=<playwright 폴더> node scripts/browser-check.cjs` — file:// 로 1280px · 390px 에서 흐름 전체를 눌러 봄(30개 × 2)
- 예시 파일 다시 만들기: `python3 scripts/make-samples.py` → `samples/` 4개 (python-docx 필요)
- 기획서 Word 다시 만들기: `python3 scripts/make-docx.py`

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| 메모장 · 워드 회의 내용 넣기 | 완료 | 붙여 넣기 · .txt(UTF-8 · 메모장 ANSI) · .docx(표는 한 행을 한 줄로). 옛 .doc · .hwp 는 2단계 |
| 회의록 서식을 같이 넣기 | 완료 | 기본 3종 + 워드 양식(.docx)이나 양식 글에서 칸 뽑기, 칸 역할로 결정 · Action Item 자리를 앎 |
| 서식에 맞춰 주요 내용 정리 | 완료(반자동 AI + 로컬 LLM + 규칙) | 프롬프트 · 답 읽기(JSON · 칸 이름 묶음 · 표), 메모 근거 점검. 실제 정답 견본과 맞추기는 2단계 |
| 필요 시 로컬 LLM | 완료(선택) | OpenAI 호환 주소로 Ollama · LM Studio · 사내 서버, 모델 목록, <think> 떼기. 모델 권장은 PC 사양 확인 후 |
| 결정 · 담당 · 기한 챙기기 | 완료 | Action Item 모아 보기, 기한 지남 · 3일 안, 담당자별 |
| 회의 녹음 → 글 · 팀 공유 · 알림 | 3단계 | 범위 확정 후 |
