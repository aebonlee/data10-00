# data10-04 · 개발장비 외관평가 Agent

외관검사 체크시트와 이슈 리스트를 이어 항목별 실제 이슈 빈도·최근성·심각도 점수를 내고, 신규 개발모델용 체크시트(중점·일반·생략 후보·신규 항목 후보)와 이슈 발생 우려 포인트 리포트를 만드는 브라우저 도구

| 항목 | 내용 |
|---|---|
| 제출자 | 이은학 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-10-20) — https://aebonlee.github.io/data10-04/ |
| 다음 개발 | 실제 체크시트·이슈 리스트로 열 연결·부위 사전·유형 사전 보정, 우려 포인트 판단 기준을 점수 규칙에 반영(기획서 10장 답을 받은 뒤) |

> 실제 체크시트·이슈 리스트는 아직 받지 않았습니다(기획서 10장에서 요청). 샘플은 같은 모양으로 지어낸 **가상 값**(모델 X-60 ~ W-300)입니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data10-04/**

처음 열면 「데이터 가져오기」 화면입니다. **「가상 샘플로 시작」** 을 누르면 체크 항목 62개와 가상 모델 8개의 이슈 146건이 들어가고 ② 이슈 매칭 화면으로 넘어갑니다. 샘플에는 일부러 다음을 심어 두었습니다.

- 신규 부품을 쓴 모델(X-120·X-160·W-220·W-300)에서 **실링·간섭 이슈가 많음**(모델 1대당 실링 약 6배·간섭 약 2.5배)
- **도장 이슈가 모델을 가리지 않고 되풀이**됨
- **체크시트에 없는 이슈** — 공구함·배터리커버(부위 자체가 없음), 캡도어 녹(그 부위에 녹 항목이 없음)
- 부위 이름을 여러 가지로 적음(CAB·캐빈·캡(좌측), C/W·카운터 웨이트, BOOM LH, HOOD …)
- 내용만으로는 유형을 알 수 없는 이슈 2건(직접 연결 연습용)

실제로 쓸 때는 지금 쓰시는 외관검사 체크시트와 이슈 리스트 엑셀을 넣고, 열 이름이 다르면 「열 연결」에서 이어 주면 됩니다. 이슈 리스트 통합문서에 「모델 정보」 시트(모델·기종·크기·신규 부품)가 있으면 함께 읽습니다. 파일은 서버로 보내지 않고 이 브라우저 안에서만 읽고 저장합니다.

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS).

| 화면 | 하는 일 |
|---|---|
| 데이터 가져오기 | 체크시트 엑셀(바꾸기·더하기) · 이슈 리스트 엑셀(여러 개) · 머리행 자동 찾기 · 열 연결 확인/수정 · 앞 5줄 미리 보기 · 행 점검 알림 · 같은 이슈 중복 제거 · 모델 정보 시트 함께 읽기 · 샘플 엑셀 내려받기 |
| ① 체크시트 마스터 | 부위·점검 항목·검사 방법·판정 기준·점검 유형·필수 — 더하기·고치기·지우기, 부위·글로 찾기, 항목별 연결 이슈 수, 마스터 엑셀 내려받기. 유형 칸이 없으면 항목 글로 추정 |
| ② 이슈 매칭 | 부위 이름 맞추기(사전 + 위치 낱말·괄호 빼기) + 이슈 내용의 낱말로 유형 찾기 → 체크 항목에 자동 연결. 확인 필요 목록(체크시트에 없는 부위·그 부위에 없는 유형·유형 못 찾음)에서 직접 연결·신규 후보·제외. **신규 항목 후보**를 (부위·유형)으로 묶어 체크시트에 더하기 |
| ③ 항목별 위험 점수 | 빈도·최근성(반감기)·심각도(상·중·하 무게) 가중 점수 0~100, 기종·크기·신규 부품으로 거르기, 부위별 합계, 모델 특성별 1대당 이슈 비교 |
| ④ 신규 모델 체크시트 | 신규 개발모델 특성(기종·크기·신규 부품·신규 부품 부위) → 닮은 모델의 이슈를 더 무겁게 반영해 위험 항목을 앞으로. **중점 · 일반 · 생략 후보 · 신규 후보**, 근거 글. 엑셀(체크시트·점수 근거·이슈 연결 3시트)·인쇄 |
| ⑤ 우려 포인트 리포트 | 상위 우려 포인트(근거 숫자·대표 이슈), 신규 부품 유무별 비교, 되풀이 항목, 신규 항목 후보. 계산된 사실만 담은 AI 프롬프트 — **모델 이름은 「모델1」 같은 별칭으로 가림(기본)**, AI 답은 모델 이름으로 되돌림(복사·붙여 넣기, 선택: 설정한 AI 서버로 자동 보내기). 인쇄/PDF·Word·엑셀·글자 복사 |
| 설정 | 점수 가중치·심각도 무게·반감기·닮은 정도 반영률·중점 기준, 부위 이름 사전, 점검 유형 낱말 사전, 모델 특성 표, AI 연결(OpenAI 호환 주소·모델·본인 키, 기억은 선택), JSON 백업 |

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음)
- 샘플 파일 다시 만들기: `node scripts/make-samples.js` → `samples/` 2개
- 기획서 Word 다시 만들기: `python3 scripts/md2docx.py docs/01_프로젝트_기획서.md docs/01_프로젝트_기획서.docx` (python-docx 필요)

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| 체크시트에 실제 이슈 발생 빈도 반영 | 완료 | 이슈 → 체크 항목 잇기, 항목별 빈도·최근성·심각도 점수. 잇는 키는 「부위 + 점검 유형」으로 가정 — 실제 공통 키는 10장 답 뒤 확정 |
| 개발모델에 따른 체크시트 최적화 | 완료 | 기종·크기·신규 부품으로 닮은 정도 반영, 중점·일반·생략 후보·신규 후보. 생략 기준·가중치는 수강생 판단 기준을 받은 뒤 보정 |
| 이슈 발생 우려 포인트 산출 | 완료(규칙 + 반자동 AI) | 근거 숫자는 규칙 계산, 문장은 AI 프롬프트(모델 이름 가림) |
| 검사 결과 입력·누적 | 2단계 | OK/NG 입력 → 이슈 리스트 자동 누적 |
| 사진·팀 공유 | 3단계 | — |
